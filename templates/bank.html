🛡️ Section D: Settlement & Reconciliation Lifecycle

Core Banking Logic

Every payment token processed by the Central Bank switch transitions through an explicit cryptographic state machine. The table below explains the real backend settlement rules:

Stage 1
Received from Merchant
Token batch submitted by merchant via authenticated HTTP. Requires valid merchant API key header (X-Merchant-Key) and matching payee binding.
Stage 2
Bank Signature Verification
Bank looks up payer public key in its authoritative registry and verifies RSA-PSS signature. Untrusted or tampered keys are rejected with zero bank trust.
Stage 3
Settled (Receipt Issued)
Committed atomically in SQLite. A cryptographically signed Bank Settlement Receipt is generated and returned for customer allowance restoration.
Stage 4
Rejected / 24h Review
Tokens already in the ledger trigger SQLite IntegrityError and are caught as double-spends. Tokens older than 24h are flagged for manual review.
